# GPX 후보 코스

공개 GPX 파일 20개(서울 20개 구의 반려견 산책 후보 경로)를 정제해 추천 후보 코스로 넣은 기록입니다. 기존 추천 엔진과 점수 체계는 바꾸지 않고, 후보만 늘렸습니다.

**이 문서의 추천 비교 수치는 반려견 프로필, 날씨, 일정의 조건 조합으로 계산한 값입니다. 실제 사용자의 만족도나 성능을 나타내지 않습니다.**

## 자료

| 항목 | 내용 |
|---|---|
| 원본 | `서울_반려견_산책_GPX.zip`. 저장소에 넣지 않고, 적재 결과만 `backend/app/data/courses_gpx.json`에 둡니다 |
| 구성 | 최상위 GPX 20개(trkpt), `서버원본/` 20개(Valhalla 응답 원본, wpt와 rte), `코스목록.csv`, `자료안내.txt` |
| 경로 출처 | Valhalla 공개 보행 경로 서버가 경유지 3개 사이에서 계산한 길. 실측 기록이나 서울시 지정 노선이 아님. © OpenStreetMap contributors (ODbL) |
| 없는 정보 | 고도, 시각, 반려견 동반 허용, 혼잡도. 20개 모두 편도 |

적재에는 최상위 GPX만 씁니다. 최상위 파일의 좌표 순서가 `서버원본/`의 wpt와 20개 모두 같고(서버원본은 구간 경계에서 같은 점이 한 번 더 나옴), 계산한 거리가 `코스목록.csv`의 편도 거리와 0.01km 안에서 맞는 것을 확인했습니다.

## 처리 방식

`backend/app/services/gpx_course_service.py`가 파일마다 아래 순서로 처리합니다. GPX 읽기는 기존 `gpx_service.parse_gpx`(DOCTYPE과 엔티티 선언 거부)를 그대로 씁니다.

| 단계 | 기준 |
|---|---|
| 정제 | 순서를 유지한 채 숫자가 아니거나 (0, 0)인 좌표, 국내 범위(위도 33~39, 경도 124~132) 밖 좌표, 0.5m 안의 연속 중복, 앞뒤가 50m 안인데 혼자 300m 넘게 튄 지점을 뺌 |
| 검증 | 남은 좌표 2개 미만, 이웃 지점 간격 2km 초과(끊긴 경로), 편도 100m 미만, 걷는 거리 10km 초과는 오류로 등록하지 않음 |
| 거리 | 정제한 좌표의 Haversine 합(측정값) |
| 형태 | 끝점이 출발점에서 50m(또는 길이의 5%) 안이면 순환형, 아니면 편도형 |
| 고도 | 기록이 있으면 1m 넘는 오르내림만 더해 상승, 하강, 1km당 상승을 냄. 없으면 비워 두고 난이도를 "확인 불가"로 둠 |
| 중복 | 같은 내용의 파일, 다른 코스와 경로가 90% 이상 겹치는 파일은 등록하지 않음. 60% 이상 겹치면 등록하되 비슷한 코스로 기록(추천 단계에서 기존 규칙대로 한 번만 나옴) |
| 지역 | 출발점이 서비스 지역 5km 안이면 그 지역, 아니면 "서울 ○○구 일대". 내 산책길 코스와 같은 기준 |
| 환경 | 선택(`--measure`). 시드 코스, 내 산책길 코스와 같은 방법으로 Overpass에서 도로, 조명, 노면, 나무, 공원을 측정. 실패하면 "확인 불가" |

**편도 코스를 왕복으로 만든 이유:** 시드 코스 16개는 모두 출발점으로 돌아오는 길이고, 엔진은 그 거리와 시간으로 반려견 활동량과 희망 시간에 맞는지 계산합니다. 편도 GPX를 그대로 넣으면 같은 거리 점수가 절반의 산책에 매겨져 점수 체계가 어긋납니다. 그래서 같은 길로 되돌아오는 왕복 경로로 만들고, 거리는 편도 측정값의 두 배로 둡니다. 편도 거리, 원래 도착점, 좌표 수, 고도는 `data_sources.gpx`에 남기고, 지도에는 원래 도착점을 "반환" 표시로 보여 줍니다.

**측정값과 추정값:** `data_sources.gpx.measured`(좌표, 편도 거리, 고도가 있으면 고도)와 `estimated`(걷는 시간은 시속 3.6km 가정, 왕복 거리는 편도의 두 배)로 나눠 적습니다. 반려견 동반 허용, 혼잡도, 난이도는 `data_sources.unknown`에 넣어 "확인 불가"로 계산하고 안전하다고 보지 않습니다. 동반 허용은 확인하지 않았다는 안내를 코스마다 붙입니다.

## DB

스키마는 바꾸지 않았습니다. 기존 `walking_courses` 행으로 넣고, 출처는 이미 있는 JSON 열 `data_sources`에 적습니다.

| 요청 항목 | 저장 위치 |
|---|---|
| source_type | `data_sources.source_type = "gpx_import"`, 코드 `gpx-<파일 이름>` |
| source_file, 원본 보존 | `data_sources.source_file`, `source_sha256`. 원본 파일은 고치지 않음 |
| route_geometry | `route` (왕복 경로), `data_sources.gpx.start`, `end` |
| distance_km, estimated_duration | `distance_km`, `duration_min` |
| elevation_gain | `data_sources.gpx.elevation` (없으면 null) |
| route_type | `data_sources.gpx.route_type` (`circular`, `one_way`) |
| is_active | 기존 `is_active` |

`courses_gpx.json`에는 `is_active`를 넣지 않습니다. 서버가 시작할 때 시드 코스와 함께 코드 기준으로 넣거나 갱신하는데, 관리자가 끈 코스를 다시 켜지 않기 위해서입니다.

## 관리 도구

```bash
cd backend
uv run python -m app.gpx_import <GPX 폴더> [--measure] [--apply] [--report 결과.json]
uv run python -m app.gpx_import --deactivate gpx-강남구_양재천   # 추천 후보에서 빼기
uv run python -m app.gpx_import --activate gpx-강남구_양재천
```

폴더 바로 아래의 `*.gpx`를 모두 읽어 성공, 중복, 오류 건수와 파일별 결과, 경고를 출력합니다. `--measure`는 아직 측정하지 못한 코스만 측정하고, `--apply`는 서버를 다시 시작하지 않아도 지금 DB에 반영합니다. 같은 폴더를 다시 실행해도 코드가 같아 행이 늘지 않습니다. 파일 이름은 NFC로 맞춰 macOS와 다른 운영체제에서 같은 코드가 나옵니다.

웹 업로드 화면은 만들지 않았습니다. 이 앱에는 관리자 권한이 없어, 공용 추천 후보를 바꾸는 업로드를 열어 두면 누구나 후보를 바꿀 수 있기 때문입니다.

## 추천 결과 비교

`recommend()`에 같은 조건(반려견 324종 × 날씨 6종 × 일정 3종, 지역마다 5,832회, 희망 시간 40분)을 넣고 기존 코스만 쓸 때와 GPX 코스를 더할 때를 비교했습니다. 피드백이 없는 신규 사용자 기준입니다.

|---|---:|---:|
| 후보 수 (기존 + GPX) | 10 + 4 | 6 + 3 |
| 후보 중 GPX 비율 | 28.6% | 33.3% |
| TOP 3 자리 중 GPX 비율 | 0.0% | 20.4% |

| 1위가 GPX인 비율 | 0.0% | 7.1% |
| 1위가 바뀐 비율 | 0.0% | 7.1% |
| 평균 추천 점수 (기존 / GPX) | 70.6 / 44.9 | 66.0 / 52.9 |
| 안전 "양호" 판정 수 (기존 / GPX) | 6,094 / 432 | 2,352 / 0 |

희망 시간을 바꾸면(날씨 맑음, 324종):

| 희망 시간 | 망원동 TOP 3 자리 중 GPX | 개포동 TOP 3 자리 중 GPX |
|---|---:|---:|
| 40분 | 0.0% | 20.2% |
| 60분 | 10.3% | 25.9% |
| 90분 | 12.6% | 26.3% |
| 120분 | 13.7% | 28.0% |

- **출처 편향 없음:** 어느 조건에서도 GPX가 TOP 3에서 차지하는 비율이 후보 비율보다 낮거나 같습니다. GPX 쪽으로 쏠리지 않습니다.
- **망원동 40분에서 GPX가 안 나오는 이유:** 망원동 GPX 4개는 왕복 50~125분이라 희망 40분과 맞지 않고, 경사, 혼잡도, 동반 허용이 "확인 불가"라 안전 단계에서 "양호"를 받지 못합니다. 희망 시간이 60분 이상이면 여의도한강공원, 홍제천 순으로 올라옵니다. 데이터가 없는 항목에 점수를 얹지 않는다는 원칙대로 동작한 결과입니다.
- **개포동:** 짧은 석촌호수(30분)와 뚝섬(50분)이 자주 TOP 3에 들어옵니다. 1위가 바뀐 경우는 7.1%입니다.
- **시연 흐름:** 기본 시연(두부, 망원동, 비 예보)의 TOP 3 코스, 점수(93.9, 89.2, 87.2), 문장은 그대로이고, 2위 코스에 5점을 두 번 주면 1위로 오르는 흐름도 그대로입니다(`test_recommender_v2.py`, `test_service_area.py`). 개포동 시연(두부, 비 예보)은 1, 2위와 추천 문장이 그대로이고, 3위가 개포로88길 골목 코스(80.4점)에서 송파구 석촌호수 서호(82.6점)로 바뀝니다.

## 남은 한계

- 실제로 걸어 보지 않은 길찾기 결과입니다. 반려견 출입 제한, 계단, 자전거 겸용, 공사와 침수는 현장 확인 전이고, CSV에 "우회 구간 지도 검토 필요"로 적힌 망원한강공원과 허준공원 코스는 설명에 그 내용을 붙였습니다.
- 고도가 없어 경사를 알 수 없습니다. 고도가 있는 GPX를 넣으면 1km당 상승 15m, 40m 기준으로 난이도가 정해집니다.
