## 추천 알고리즘 v2

추천 고도화 지시서의 검증 시나리오 14개는 `backend/tests/test_recommender_v2.py`에 있고, 시나리오별 확인 내용과 오프라인 비교 결과, 검증하지 못한 항목은 [추천 알고리즘](RECOMMENDER.md)에 정리했습니다. **평가 수치는 조건 조합과 합성 사용자로 계산한 값이며, 실제 사용자 데이터로 검증한 것이 아닙니다.** 위 표의 6번 시나리오는 v2에서 5점 두 번이면 2위가 1위로 오르도록 바뀌었습니다.

원격 `main`의 경로 생성 코드와의 호환은 임시 복제본에서 시험 병합해 확인했습니다. 백엔드 테스트 808개가 통과했고, 충돌한 5개 파일 중 `api.py`, `engine.py`만 풀어 돌렸습니다. 병합 후 E2E와 경로 생성 화면은 확인하지 않았습니다.

## GPX 호환성

| 확인 | 방법 | 결과 |
|---|---|---|
| GPX 1.1 표준 | 앱이 내보낸 파일 3종(기록, 시각 없음, 공유용)을 TopoGrafix 공식 XSD로 검증 (lxml) | 모두 통과 |
| 다른 도구가 읽기 | 내보낸 파일을 gpxpy로 읽기 | 트랙, 구간, 지점, 이름(특수문자와 이모지 포함), 고도, UTC 시각 일치 |
| 다른 도구의 파일 읽기 | gpxpy가 쓴 GPX 1.1, 1.0 파일을 앱으로 가져오기 | 지점, 구간, 고도, 시각(서울 시간 변환) 일치 |
| 피트니스 앱 형식 | 스트라바, 가민 형식을 본뜬 확장 태그(심박 등) 포함 파일 | 확장 태그 안의 값에 영향받지 않고 좌표와 시각만 읽음 |
| 파일 이름 | 한글 이름은 `filename*`(UTF-8), 한글을 모르는 프로그램용 영문 대체 이름을 함께 줌 | 예: `pawpath_morning-walk_20261031.gpx` |
| 실제 기기와 앱 파일 | 공개 저장소의 실제 GPX 51개를 가져오고 다시 내보내기 (아래) | 읽은 36개 모두 내보낸 파일이 XSD 통과, 다시 가져오면 좌표, 시각, 고도가 원본과 똑같음 |

## 실제 기기와 앱이 만든 GPX

gpxpy와 togeojson 저장소에 공개된 GPX 시험 파일 51개(실제 기기와 앱 내보내기 포함)로 확인했습니다. 파일은 검증에만 쓰고 저장소에 넣지 않았습니다.

| 결과 | 파일 |
|---|---|
| 읽음 36개 | 스트라바(2), 애플워치, Apple Health 내보내기, 가민 Connect, 가민 eTrex 20x, 가민 Oregon 600, 가민 MapSource, OsmAnd, OpenCPN, NikePlus, OpenStreetMap.org, BRouter, ExpertGPS, GPSBabel, GDAL 등. 확장 태그, BOM, 버전 표기 없음, 여러 트랙, 빈 구간, 시각 없는 경로 포함 |
| 거부 15개 | 트랙 없이 장소 표시(waypoint)만 있는 파일 7개, 좌표가 모두 `undefined`인 파일 1개, 트랙이 비어 있는 파일 5개, 지점이 1개뿐인 파일 2개. 모두 이유를 정확히 안내 |

나눈 구간이 있는 11개는 2초에 184m를 움직인 GPS 오류(GPSBabel 파일 4개)나, 시각 없이 수백 km 떨어진 지점을 담은 시험용 파일입니다.

## 실제 환경에서 확인한 내용

자동 테스트는 외부 서비스에 의존하지 않도록 모의 날씨로 돌립니다. 아래는 실제 서비스를 연결해 별도로 확인했습니다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 실제 LLM | 로컬 Ollama `gemma4:e4b`로 곧 비, 폭염, 한파 조건 생성 | 추천 3개 문장을 약 5~9초에 생성, 모두 사실 검증 통과, 점수 불변 |
| 실제 날씨 | Open-Meteo 호출 | 정상. 출처를 화면에 표시 |
| 실제 길찾기 | OSRM 도보 경로, 망원역에서 코스 출발점까지 | 약 420m 경로와 회전 안내 |
| 위치 로그 | 전체 흐름 실행 후 서버 로그 검색 | 좌표 0건 |
| 오류 | 전체 흐름 실행 중 서버와 브라우저 | 서버 500 0건, 브라우저 오류 0건 |
| 옛 DB | 새 컬럼이 없는 DB를 열어 자동 보강 | 데이터 유지, 반복 실행 안전 |
| 개포동 코스 | `SERVICE_AREA=gaepo`, 위치를 새롬관으로 설정해 실제 날씨, 길찾기, LLM으로 전체 흐름 실행 | 코스 6개만 표시, 필수 추천 문장 생성, 출발점까지 실제 도보 경로, 2위에 5점을 주면 1위로 상승, 서버 500 0건 |

## 검증하지 못한 것

- **실제 DB의 마이그레이션:** 개발 DB의 사본으로만 확인했습니다. 원본은 서버를 다시 켤 때 처음 올라갑니다.
- **실제 Google로 처음 로그인해 프로필 설정하기:** 가짜 Google 서버로 리디렉션까지만 확인했습니다. 실제 휴대폰과 화면 읽기 도구로는 프로필 화면을 써 보지 않았습니다.
- **PostgreSQL의 프로필:** 구문은 호환되게 썼지만 실제 연결에서 돌려 보지 않았습니다.
- **산책길 커뮤니티의 실제 환경:** 실제 휴대폰으로 걷지 않았고 위치 에뮬레이션으로 확인했습니다. PostgreSQL에서는 돌려 보지 않았습니다. 산책 인증은 브라우저가 보낸 `tracking_source`를 믿으므로 API를 직접 호출하는 위조는 막지 못합니다.
- **실제 Google 본인 재확인:** 가짜 Google 서버로만 확인했습니다. Google 문서의 `prompt` 값으로는 비밀번호를 다시 묻게 강제할 수 없어, 계정 선택과 계정 일치까지만 확인합니다.
- **실제 디스크 장애와 다른 디스크의 백업:** 파일을 손상시키고 지워서 재현했습니다. 원격 복사는 구현하지 않았습니다.
- **PostgreSQL의 탈퇴와 백업:** 탈퇴 순서는 SQLite에서 외래 키를 켜서 확인했습니다. 자동 백업과 복구 명령은 SQLite만 지원합니다.
- **실제 시간 경과:** 7일, 30일, 14일은 DB의 시각이나 파일 이름의 시각을 바꿔 확인했습니다.
- **WebKit의 사진 캐시 삭제:** `only-if-cached`를 지원하지 않아 Chromium에서만 확인했습니다.
- **코스 현장 확인:** 망원동과 개포동 코스 모두 OpenStreetMap 기준이며, 팀이 현장에서 걸어 보지 않았습니다. 통행 제한이나 공사는 지도와 다를 수 있습니다.
- **실제 휴대폰으로 야외 도보:** GPS 동작은 브라우저 위치 에뮬레이션으로 확인했습니다. 실제 GPS 오차, 건물 사이 신호, 화면 꺼짐 방지는 확인하지 못했습니다.
- **실제 휴대폰으로 산책 기록:** 화면 꺼짐, 다른 앱 전환, 실제 GPS 오차, 화면 꺼짐 방지는 확인하지 못했습니다. 위치는 브라우저 에뮬레이션으로 넣었습니다.
- **실제 iPhone Safari:** 같은 엔진인 WebKit으로만 확인했습니다.
- **실제 앱과 주고받기:** 공개된 실제 기기와 앱 파일 51개는 확인했지만, 팀이 직접 앱에서 내려받은 파일이나 PawPath가 내보낸 파일을 스트라바, 가민 같은 앱에 다시 올려 보는 것은 하지 않았습니다.
- **휴대폰에서 Google 로그인:** 고정 도메인을 리디렉션 URI로 등록한 터널 환경에서는 확인하지 않았습니다.
- **휴대폰 사진:** 아이폰 HEIC 사진과 안드로이드 사진을 실제 휴대폰에서 올려 보지 않았습니다. 브라우저 캔버스로 만든 JPEG에 위치 정보를 넣어 확인했습니다.
- **기기 저장 공간 부족:** 임시 저장 실패 안내는 구현했지만 실제로 저장 공간을 채워 확인하지는 않았습니다.
- **PostgreSQL:** `DATABASE_URL` 설정과 컬럼 추가 구문은 호환되게 작성했지만 실제 연결은 하지 않았습니다.
- **실시간 강수 감지:** 구현하지 않았습니다. 시간별 예보로 판단합니다.
- **LLM 품질의 통계적 평가:** 세 가지 날씨 조건을 직접 읽어 확인했을 뿐, 많은 사례로 평가하지는 않았습니다.
- **추천의 실제 성능:** 실제 사용자 데이터가 없어 선택률, 만족도, 피드백 전후 변화를 측정하지 못했습니다. 자세한 내용은 [추천 알고리즘](RECOMMENDER.md#구현하거나-검증하지-못한-것)에 있습니다.
