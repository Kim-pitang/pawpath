## 실제 환경에서 확인한 내용

자동 테스트는 외부 서비스에 의존하지 않도록 모의 날씨로 돌립니다. 아래는 실제 서비스를 연결해 별도로 확인했습니다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 실제 LLM | 로컬 Ollama `gemma4:e4b`로 곧 비, 폭염, 한파 조건 생성 | 추천 3개 문장을 약 5~9초에 생성, 모두 사실 검증 통과, 점수 불변 |
| 실제 날씨 | Open-Meteo 호출 | 정상. 출처를 화면에 표시 |
| 실제 길찾기 | OSRM 도보 경로, 망원역에서 코스 출발점까지 | 약 420m 경로와 회전 안내 |
| 위치 로그 | 전체 흐름 실행 후 서버 로그 검색 | 좌표 0건 |
| 오류 | 전체 흐름 실행 중 서버와 브라우저 | 서버 500 0건, 브라우저 오류 0건 |
| 옛 DB | 새 컬럼이 없는 DB를 열어 자동 보강 | 데이터 유지, 반복 실행 안전 |
| 개포동 코스 | `SERVICE_AREA=gaepo`, 위치를 새롬관으로 설정해 실제 날씨, 길찾기, LLM으로 전체 흐름 실행 | 코스 6개만 표시, 필수 추천 문장 생성, 출발점까지 실제 도보 경로, 2위에 5점을 주면 1위로 상승, 서버 500 0건 |

## 검증 중 발견해 고친 문제

| 문제 | 조치 |
|---|---|
| 1점을 준 코스가 선택 이력 때문에 점수가 오름 | 낮게 평가한 코스는 이력에서 제외 |
| LLM이 "공원 내에 화장실"처럼 근거 없는 위치를 말함 | 위치 표현 차단, 프롬프트에 규칙 추가 |
| 위험요인 문구의 낱말까지 막아 폭염 때 문장이 전부 거부됨 | 위험요인에 있는 낱말은 근거로 인정 |
| 체감 21°C를 "더운 시간"으로 안내 | 쾌적 범위를 넘을 때만 더위로 판정 |
| 복귀 경로가 25m보다 짧으면 도착 판정이 나지 않음 | 편도 경로는 들어오자마자 도착 가능하게 수정 |
| 시연용 걷기에서 복귀를 고르면 안내 없이 바로 도착 처리됨. 기존 테스트는 첫 화면만 확인해 놓침 | 걸은 거리를 경로와 묶어 수정, 1초 뒤에도 복귀 중인지 확인하는 테스트 추가 |
| 동네숲 코스를 "공원 코스"로 설명했으나 실측상 공원을 지나지 않음 | 공원 포함 해제, "동네 코스"로 설명 |
| "차량 노출 적음"으로 추정한 코스에 큰 도로 19% 구간 존재 | 차량 노출을 OSM 실측값으로 교체 |
| 안전 점수가 조금 높을 뿐인데 대체 코스로 권함 | 위험 수준이 낮거나 10점 이상 높을 때만 권함 |

## 검증하지 못한 것

- **코스 현장 확인:** 망원동과 개포동 코스 모두 OpenStreetMap 기준이며, 팀이 현장에서 걸어 보지 않았습니다. 통행 제한이나 공사는 지도와 다를 수 있습니다.
- **실제 휴대폰으로 야외 도보:** GPS 동작은 브라우저 위치 에뮬레이션으로 확인했습니다. 실제 GPS 오차, 건물 사이 신호, 화면 꺼짐 방지는 확인하지 못했습니다.
- **PostgreSQL:** `DATABASE_URL` 설정과 컬럼 추가 구문은 호환되게 작성했지만 실제 연결은 하지 않았습니다.
- **실시간 강수 감지:** 구현하지 않았습니다. 시간별 예보로 판단합니다.
- **LLM 품질의 통계적 평가:** 세 가지 날씨 조건을 직접 읽어 확인했을 뿐, 많은 사례로 평가하지는 않았습니다.
