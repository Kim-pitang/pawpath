## GPX 호환성

| 확인 | 방법 | 결과 |
|---|---|---|
| GPX 1.1 표준 | 앱이 내보낸 파일 3종(기록, 시각 없음, 공유용)을 TopoGrafix 공식 XSD로 검증 (lxml) | 모두 통과 |
| 다른 도구가 읽기 | 내보낸 파일을 gpxpy로 읽기 | 트랙, 구간, 지점, 이름(특수문자와 이모지 포함), 고도, UTC 시각 일치 |
| 다른 도구의 파일 읽기 | gpxpy가 쓴 GPX 1.1, 1.0 파일을 앱으로 가져오기 | 지점, 구간, 고도, 시각(서울 시간 변환) 일치 |
| 피트니스 앱 형식 | 스트라바, 가민 형식을 본뜬 확장 태그(심박 등) 포함 파일 | 확장 태그 안의 값에 영향받지 않고 좌표와 시각만 읽음 |
| 파일 이름 | 한글 이름은 `filename*`(UTF-8), 한글을 모르는 프로그램용 영문 대체 이름을 함께 줌 | 예: `pawpath_morning-walk_20261031.gpx` |
| 실제 기기와 앱 파일 | 공개 저장소의 실제 GPX 51개를 가져오고 다시 내보내기 (아래) | 읽은 36개 모두 내보낸 파일이 XSD 통과, 다시 가져오면 좌표, 시각, 고도가 원본과 똑같음 |

## 실제 기기와 앱이 만든 GPX

gpxpy와 togeojson 저장소에 공개된 GPX 시험 파일 51개(실제 기기와 앱 내보내기 포함)로 확인했습니다. 파일은 검증에만 쓰고 저장소에 넣지 않았습니다.

| 결과 | 파일 |
|---|---|
| 읽음 36개 | 스트라바(2), 애플워치, Apple Health 내보내기, 가민 Connect, 가민 eTrex 20x, 가민 Oregon 600, 가민 MapSource, OsmAnd, OpenCPN, NikePlus, OpenStreetMap.org, BRouter, ExpertGPS, GPSBabel, GDAL 등. 확장 태그, BOM, 버전 표기 없음, 여러 트랙, 빈 구간, 시각 없는 경로 포함 |
| 거부 15개 | 트랙 없이 장소 표시(waypoint)만 있는 파일 7개, 좌표가 모두 `undefined`인 파일 1개, 트랙이 비어 있는 파일 5개, 지점이 1개뿐인 파일 2개. 모두 이유를 정확히 안내 |

나눈 구간이 있는 11개는 2초에 184m를 움직인 GPS 오류(GPSBabel 파일 4개)나, 시각 없이 수백 km 떨어진 지점을 담은 시험용 파일입니다.

## Google 로그인

팀이 Google Cloud에서 발급한 실제 클라이언트로 개발 서버에서 로그인을 확인했습니다. 위조와 장애 상황은 실제 Google로 만들 수 없어 가짜 Google 서버로 재현했습니다. 가짜 서버는 실제 Google처럼 클라이언트 비밀값, 리디렉션 URI, PKCE 검증값을 확인합니다.

| 항목 | 확인한 내용 | 결과 |
|---|---|---|
| Google로 보내기 | 클라이언트 ID, 리디렉션 URI, `openid email profile`, PKCE S256, 40자 이상의 state와 nonce. DB에는 state 해시만 | 통과 |
| 토큰 교환 | 서버가 코드, 비밀값, 리디렉션 URI, PKCE 검증값을 보내고 challenge와 일치 | 통과 |
| 로그인 CSRF | 다른 브라우저에서 시작한 state, 바꾼 state, 다시 쓴 state, 10분 지난 state를 모두 거부하고 Google에 요청하지 않음 | 통과 |
| 토큰 확인 | 다른 앱의 토큰, 다른 발급자, 만료, nonce 불일치, 사용자 ID 없음, 형식 오류를 거부하고 보호자를 만들지 않음 | 통과 |
| 장애 | 토큰 엔드포인트 400, 연결 시간 초과, 응답 형식 오류, 사용자의 취소를 이유별로 안내 | 통과 |
| 돌아갈 주소 | `//evil.example`, `https://evil.example`, `javascript:`는 홈으로 바꿈 | 통과 |
| 계정 | 같은 Google 계정은 같은 보호자, 다른 계정과 시연 보호자와는 분리, 확인되지 않은 이메일은 저장하지 않음 | 통과 |
| 로그 | 서버 로그와 접근 로그에 승인 코드, state, 토큰, 비밀값이 남지 않음 | 통과 |

| 권한 | 다른 계정과 시연 보호자는 목록, 조회, 길찾기, 주변 시설, 안전 평가, 산책 기록, 대체 경로, 추천, 등록 모두에서 남의 코스를 볼 수 없음. 로그인 필수 모드에서도 코스 목록은 공개, 남의 코스는 404 | 통과 |
| 빼기와 삭제 | 추천과 지도에서 빠지고, 이 코스로 남긴 산책 기록과 길 안내는 주인에게 계속 열림 | 통과 |
| 거부 | 서비스 지역 밖, 0.1km 미만, 10km 초과, 100m 넘게 끊긴 구간을 이유와 함께 거부 | 통과 |
| 측정 | 가짜 Overpass로 측정값이 엔진 입력에 들어감. 실패, 끝나지 않는 측정(5분), 다시 등록한 뒤 도착한 옛 결과를 처리 | 통과 |
| 실제 Overpass | 시드 코스 3개의 경로를 내 산책길로 등록해 측정. 도로, 조명, 노면 값이 시드 코스에 저장된 값과 같음 | 통과. 응답에 34~41초, 한 번은 두 서버 모두 시간 초과 |
| 실제 브라우저 | 실제 Overpass로 GPX 가져오기, 등록, 지도와 길 안내까지 | 등록 응답 74ms, 측정 결과가 15.5초 뒤 화면에 자동 반영 |

## 실제 환경에서 확인한 내용

자동 테스트는 외부 서비스에 의존하지 않도록 모의 날씨로 돌립니다. 아래는 실제 서비스를 연결해 별도로 확인했습니다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 실제 LLM | 로컬 Ollama `gemma4:e4b`로 곧 비, 폭염, 한파 조건 생성 | 추천 3개 문장을 약 5~9초에 생성, 모두 사실 검증 통과, 점수 불변 |
| 실제 날씨 | Open-Meteo 호출 | 정상. 출처를 화면에 표시 |
| 실제 길찾기 | OSRM 도보 경로, 망원역에서 코스 출발점까지 | 약 420m 경로와 회전 안내 |
| 위치 로그 | 전체 흐름 실행 후 서버 로그 검색 | 좌표 0건 |
| 오류 | 전체 흐름 실행 중 서버와 브라우저 | 서버 500 0건, 브라우저 오류 0건 |
| 옛 DB | 새 컬럼이 없는 DB를 열어 자동 보강 | 데이터 유지, 반복 실행 안전 |
| 개포동 코스 | `SERVICE_AREA=gaepo`, 위치를 새롬관으로 설정해 실제 날씨, 길찾기, LLM으로 전체 흐름 실행 | 코스 6개만 표시, 필수 추천 문장 생성, 출발점까지 실제 도보 경로, 2위에 5점을 주면 1위로 상승, 서버 500 0건 |

## 검증 중 발견해 고친 문제

| 문제 | 조치 |
|---|---|
| 1점을 준 코스가 선택 이력 때문에 점수가 오름 | 낮게 평가한 코스는 이력에서 제외 |
| LLM이 "공원 내에 화장실"처럼 근거 없는 위치를 말함 | 위치 표현 차단, 프롬프트에 규칙 추가 |
| 위험요인 문구의 낱말까지 막아 폭염 때 문장이 전부 거부됨 | 위험요인에 있는 낱말은 근거로 인정 |
| 체감 21°C를 "더운 시간"으로 안내 | 쾌적 범위를 넘을 때만 더위로 판정 |
| 복귀 경로가 25m보다 짧으면 도착 판정이 나지 않음 | 편도 경로는 들어오자마자 도착 가능하게 수정 |
| 시연용 걷기에서 복귀를 고르면 안내 없이 바로 도착 처리됨. 기존 테스트는 첫 화면만 확인해 놓침 | 걸은 거리를 경로와 묶어 수정, 1초 뒤에도 복귀 중인지 확인하는 테스트 추가 |
| 동네숲 코스를 "공원 코스"로 설명했으나 실측상 공원을 지나지 않음 | 공원 포함 해제, "동네 코스"로 설명 |
| "차량 노출 적음"으로 추정한 코스에 큰 도로 19% 구간 존재 | 차량 노출을 OSM 실측값으로 교체 |
| 안전 점수가 조금 높을 뿐인데 대체 코스로 권함 | 위험 수준이 낮거나 10점 이상 높을 때만 권함 |
| WebKit에서 산책 기록 거리가 0으로 남고 저장이 거부됨. WebKit이 위치 시각을 마이크로초로 줘서 좌표마다 끊김으로 판정 | 좌표를 받은 시각을 쓰도록 수정, 마이크로초 시각을 흉내 낸 테스트 추가(수정 전 실패 확인) |
| 산책길 수정 API에 `null`을 보내면 500 오류 | `pet_id` 외에는 422로 거부, 테스트 추가 |
| 한글 이름의 GPX 영문 대체 파일 이름이 `pawpath_-----.gpx`로 깨짐 | 영문만 남기고 없으면 `walk`로 표시 |
| 기존 복귀 E2E가 출발 직후 비를 내려, 응답 속도에 따라 바로 도착으로 끝남 | 앱 동작은 맞음(출발점 25m 안). 테스트가 코스를 10% 걸은 뒤 비를 내리게 수정 |
| 버전 표기가 없는 실제 기기 GPX를 "지원하지 않는 버전"으로 거부 | 경고와 함께 읽음 |
| 장소 표시만 있는 파일, 좌표가 모두 잘못된 파일을 "좌표가 없다"고만 안내 | 원인을 그대로 안내 |
| 내보낼 때 좌표를 소수 7자리, 고도를 2자리로 반올림해 다시 가져오면 값이 달라짐 | 반올림 없이 원래 값을 씀(지수 표기는 풀어 씀) |
| 같은 초에 여러 지점을 찍는 GPSBabel 파일에서 10m 이동을 순간 이동으로 나눔. 고친 직후에는 같은 시각의 정상 이동까지 나눠 거리가 2.69km에서 2.32km로 줄어듦 | 100m 이상일 때만 속도로 판단하고, 시각이 같으면 시각이 없는 것처럼 5km 기준을 씀. 원래 거리(2.70km) 회복 |
| 세션이 만료된 뒤 마이페이지에 이전 오류가 계속 남음 | 반려동물이 바뀌면 오류를 지움 |
| 아이디 앞뒤 공백, 대문자 입력이 형식 검사에서 거부됨 | 검사 전에 공백을 지우고 소문자로 바꿈 |
| Google 콜백 주소의 승인 코드와 state가 서버 접근 로그에 그대로 남음 | 접근 로그에서 콜백 주소의 값을 지움 |
| 내 산책길 등록 때 Overpass 응답을 기다려 버튼이 30~40초 멈추고, 한 번은 실패 | 등록은 바로 끝내고 측정은 응답 뒤에 함. 화면이 측정 완료까지 자동으로 다시 읽음 |
| 공원 판정 기준(경로의 20%)이 팀 판정과 달라 망원초록길(18%)이 공원 없음이 됨 | 시드 코스 16개와 비교해 1%로 맞춤 |
| Google 버튼 E2E가 리디렉션된 Google 주소를 가로채지 못해 실제 Google 로그인 주소를 가짜 클라이언트 ID로 한 번 열었음 | 브라우저를 보내지 않고 서버의 리디렉션 응답만 검사하도록 수정 |
| 산책 기록 탭: 잘못 누르거나 두 번 남긴 기록을 지울 수 없어 "피드백을 기다리는 산책"에 계속 쌓임 | 피드백 전 기록은 지울 수 있게 함(코스 방문 수도 되돌림). 피드백을 남긴 기록은 학습에 반영되어 지우지 않음 |
| 산책 기록 탭: 피드백 대기 목록에 코스 이름만 나와 같은 코스의 산책을 구분할 수 없고, 쌓이면 지난 산책이 한참 아래로 밀림 | 날짜, 시각, 시간 표시. 최근 3개만 먼저 보여 주고 지난 산책은 10개씩 |
| 산책 기록 탭: GPS 없이 기록하면 출발 시각이 항상 지금이라, 아침 산책을 저녁에 기록하면 저녁 시간대로 학습됨 | "다른 시각에 다녀왔어요"로 출발 시각 입력. 끝나지 않은 시각은 화면과 서버에서 거부 |
| 산책 기록 탭: 피드백 버튼이 비활성일 때 이유가 없음 | 아직 고르지 않은 항목을 버튼 아래에 표시 |
| 산책 기록 탭: 선호도가 그대로인데 "50점에서 50점으로 올랐어요"로 표시. 실제로 4·3점과 "다른 곳이 좋아요"를 주면 나옴 | 화면에 보이는 점수로 비교해 "그대로예요"로 표시 |
| 산책 기록 탭: 추천에서 넘어와 기록한 뒤 이어서 다른 산책을 기록하면 같은 추천 번호가 다시 붙음 | 기록 후 주소에서 코스와 추천 번호를 지움 |

## 검증하지 못한 것

- **코스 현장 확인:** 망원동과 개포동 코스 모두 OpenStreetMap 기준이며, 팀이 현장에서 걸어 보지 않았습니다. 통행 제한이나 공사는 지도와 다를 수 있습니다.
- **실제 휴대폰으로 야외 도보:** GPS 동작은 브라우저 위치 에뮬레이션으로 확인했습니다. 실제 GPS 오차, 건물 사이 신호, 화면 꺼짐 방지는 확인하지 못했습니다.
- **실제 휴대폰으로 산책 기록:** 화면 꺼짐, 다른 앱 전환, 실제 GPS 오차, 화면 꺼짐 방지는 확인하지 못했습니다. 위치는 브라우저 에뮬레이션으로 넣었습니다.
- **실제 iPhone Safari:** 같은 엔진인 WebKit으로만 확인했습니다.
- **실제 앱과 주고받기:** 공개된 실제 기기와 앱 파일 51개는 확인했지만, 팀이 직접 앱에서 내려받은 파일이나 PawPath가 내보낸 파일을 스트라바, 가민 같은 앱에 다시 올려 보는 것은 하지 않았습니다.
- **휴대폰에서 Google 로그인:** 고정 도메인을 리디렉션 URI로 등록한 터널 환경에서는 확인하지 않았습니다.
- **휴대폰 사진:** 아이폰 HEIC 사진과 안드로이드 사진을 실제 휴대폰에서 올려 보지 않았습니다. 브라우저 캔버스로 만든 JPEG에 위치 정보를 넣어 확인했습니다.
- **기기 저장 공간 부족:** 임시 저장 실패 안내는 구현했지만 실제로 저장 공간을 채워 확인하지는 않았습니다.
- **PostgreSQL:** `DATABASE_URL` 설정과 컬럼 추가 구문은 호환되게 작성했지만 실제 연결은 하지 않았습니다.
- **실시간 강수 감지:** 구현하지 않았습니다. 시간별 예보로 판단합니다.
- **LLM 품질의 통계적 평가:** 세 가지 날씨 조건을 직접 읽어 확인했을 뿐, 많은 사례로 평가하지는 않았습니다.
