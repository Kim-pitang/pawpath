# 추천 알고리즘

mungo의 산책 추천 엔진(`backend/app/recommender`)이 무엇을 입력으로 받아 어떻게 안전을 판단하고, 점수를 매기고, 피드백으로 배우는지 설명합니다. 이 문서의 산식, 가중치, 임계값은 커밋 `5f74f2d`의 소스 코드에서 옮겼습니다. 기본 버전은 `rule-v2`이고, `RECOMMENDER_VERSION=v1`로 이전 동작(`rule-v1`)으로 되돌릴 수 있습니다.

**이 문서의 성능 수치는 모두 조건 조합이나 가상 사용자로 계산한 값입니다. 실제 사용자의 만족도나 성능을 나타내지 않습니다.**

## 추천 개요

추천은 외부 AI를 부르지 않고 직접 구현한 **규칙 기반 개인화 모델**과 **온라인 피드백 학습**으로 정합니다. LLM은 선택 기능이며 확정된 결과의 문장만 다듬습니다.

```text
STEP 1 후보      반려견 출입 가능, 가능 시간 안에 예보가 있는 코스
STEP 2 안전      위험한 날씨와 차단 조건은 이유와 함께 제외. 위험 수준은 강한 경고와 함께 뒤로
STEP 3 개인화    기본 적합도(4개 묶음) + 피드백 조정 - 안전 감점 - 미선택 감점
STEP 4 랭킹      안전 단계 → 점수 순. 경로가 겹치는 코스는 한 번만, 다녀온 코스만 남으면 새 코스 하나
```

| 모듈 | 하는 일 |
|---|---|
| `features.py` | 반려동물 프로필을 추천용 특성값으로 변환 |
| `timeslots.py` | 시간별 예보로 출발 시각 평가 |
| `safety.py` | 11개 항목 안전 평가와 차단 조건 |
| `course_scoring.py` | 코스 × 출발 시각 점수 |
| `engine.py` | 전체 흐름, 랭킹, 대체 코스, 탐색 |
| `diversity.py` | 경로 겹침 판정 |
| `preference.py` | 피드백 학습 |
| `profile.py` | 선호 프로필(선호 거리, 걸음 속도 등) |
| `explain.py`, `explain_guard.py` | 근거 문장 생성과 LLM 문장 검증 |
| `evaluation.py` | 평가 지표 |
| `config.py` | 가중치, 버전, `Ranker` 인터페이스 |

엔진은 DB와 웹 프레임워크에 의존하지 않는 순수 Python 모듈이라 같은 입력으로 단위 테스트할 수 있고, 난수를 쓰지 않아 같은 입력은 같은 순위를 냅니다.

## 설계 목표

| 목표 | 설계 |
|---|---|
| 안전이 개인화보다 먼저 | 안전을 점수의 한 항목으로 섞으면 선호 점수가 위험을 상쇄할 수 있습니다. 그래서 안전을 앞 단계의 필터로 두고, 위험 수준 코스는 점수가 높아도 안전한 코스 뒤로 보냅니다. |
| 데이터가 없어도 동작하되 아는 척하지 않음 | 신규 사용자는 프로필만으로 추천합니다. 데이터가 없는 항목은 "확인 불가"로 두고 안전하다고 보지 않으며, 날씨를 모르면 날씨를 칭찬하지 않습니다. |
| 모든 점수는 설명 가능 | 묶음별 점수, 가중치, 근거, 출처를 저장하고 화면에 보여 줍니다. 추정값은 추정이라고 밝힙니다. |
| 피드백은 보이게, 그러나 과하지 않게 | 피드백 한 번에 순위가 뒤집히지 않도록 조정 폭을 ±15점으로 제한하고, 건수에 따라 비중을 늘립니다. |
| 직접 개발, 교체 가능 | 실제 피드백이 0건이고 코스가 지역당 6~10개라 학습 순위 모델의 입력이 부족합니다. 규칙 기반으로 시작하고, 순위 계산은 `Ranker` 인터페이스로 분리해 데이터가 쌓이면 학습 모델과 비교할 수 있게 했습니다. |

### v1에서 v2로 바꾼 이유

v1(6항목 가중합)을 반려견 프로필 324종 × 날씨 6종 × 일정 3종, 지역마다 5,832회 넣어 점검했습니다.

| 점검 | 결과 |
|---|---|
| 같은 입력의 일관성 | 일관됨. 난수를 쓰지 않고, 같은 날 호출 시각만 바꾼 표본 36개의 순위도 같음 |
| 가중치 합계 | 100%가 아님. 사용자 선호도 10%가 따로 더해지고 과거 선호도가 최대 20%p 늘어 110~128% |
| 항목의 변별력 | 같은 조건에서 코스 간 기여도 표준편차: 활동량 3.3, 성향 2.8, 일정 2.7, 날씨 0.8, 안전 0.7점. 날씨(25%)와 안전(10%)은 순위를 거의 가르지 못함 |
| 기본값 왜곡 | 시드의 `is_familiar`(팀이 시연 보호자 기준으로 붙인 "집 근처" 표시) 3곳이 익숙한 길 선호 프로필 1위의 72.8%. 방문 0회인데 "익숙한 코스"라고 설명 |
| 피드백 반영 | 산책 1회와 5점이 익숙함, 선택 이력, 코스 선호도, 익숙한 길 보너스 네 곳에 겹쳐 약 +12점. 5점 한 번에 9위→4위, 4위→1위. 1점 한 번으로는 1위 코스가 그대로 1위 |
| 안전과 개인화 | 차단 조건은 제외함. 위험 수준 코스는 개인화 점수 덕분에 안전한 코스 위로 올 수 있음 (개포 조건 조합의 2.3%) |
| 날씨 결측 | 날씨 API가 실패하면 모의 날씨(17°C)로 대신하면서 "기온 양호", "산책하기 좋아요"라고 안내. 예보가 없으면 이유 없이 실내 놀이 안내 |
| 비슷한 코스 | 서울함공원 강변 왕복은 경로 전체가 한강 종주 코스 안에 있음. 함께 TOP 3에 오르는 경우가 1.5% |
| 이력 | TOP 3 점수는 JSON으로 남지만 알고리즘 버전, 날씨 기준 시각, TOP 3 밖 후보, 산책 시작은 없음 |

## 입력 특성

| 입력 | 내용 | 출처 |
|---|---|---|
| 반려동물 프로필 | 크기, 나이, 체중, 활동량, 성격, 산책 선호(익숙한 길·새 길), 더위 민감도, 낯선 환경 반응 | 보호자 입력 |
| 보호자 일정 | 산책 가능 시간대, 희망 산책 시간, 하루 횟수 | 보호자 입력 (프로필마다) |
| 사용자 선호 | 선호 거리, 선호 시간대 | 보호자 입력 (선택) |
| 날씨 | 시간별 체감온도, 강수 확률과 강수량, 습도, 바람, 자외선, 낮밤 | Open-Meteo 시간별 예보 |
| 코스 | 경로, 거리, 예상 시간, 공원, 포장, 강변 등 경관 태그, 도로 등급 비율, 조명, 노면, 나무, 시설 | OSRM, OpenStreetMap, 팀 추정 |
| 학습 상태 | 코스 선호, 코스 특성 가중치, 시간대 선호, 선호 거리, 걸음 속도, 방문 수, 미선택 일수 | 산책 기록과 피드백 |

추천 요청은 사용자 위치를 받지 않습니다. 서비스 지역(망원동, 개포동) 하나의 코스와 그 지역 날씨로 추천합니다.

## 반려동물 프로필

`features.py`가 프로필을 다음 특성값으로 바꿉니다. 일반적인 산책 지침을 참고한 서비스 휴리스틱이며 수의학적 기준이 아닙니다.

| 특성값 | 계산 |
|---|---|
| 생애 단계 | 1살 미만은 어린 강아지. 노령 기준 나이는 크기별 소형 10살, 중형 8살, 대형 7살 |
| 권장 산책 시간 | 크기별 기본(소형 30분, 중형 45분, 대형 60분) × 활동량(적음 0.75, 보통 1.0, 많음 1.3) × 생애 단계(어린 0.6, 성견 1.0, 노령 0.7) |
| 권장 거리 | 권장 시간 × 크기별 걸음 속도(소형 3.0, 중형 3.6, 대형 4.2km/h) |
| 낯선 길 허용도 (0~1) | 산책 선호(익숙한 길 0.2, 새 길 0.8) + 낯선 환경 반응(차분 +0.1, 조심 0, 불안 −0.15) + 성격(활발 +0.05, 소심 −0.05, 호기심 +0.1) |
| 혼잡 허용도 (0~1) | 성격(활발 0.8, 호기심 0.6, 소심 0.2) + 낯선 환경 반응 |
| 오르막 허용도 (0~1) | 활동량(0.3, 0.6, 0.9). 어린 강아지와 노령견은 −0.3 |
| 쾌적 체감온도 | 기본 5~22°C. 소형 하한 +1, 대형 하한 −3, 더위 민감도(낮음 +3, 보통 0, 높음 −3)로 상한 조정, 25kg 이상 상한 −1, 5kg 미만 하한 +1, 어린 강아지·노령견 하한 +2·상한 −2 |
| 산책 제외 온도 | 쾌적 하한 −15°C 이하, 쾌적 상한 +11°C 이상 |

## 날씨 데이터

Open-Meteo에서 **시간별 예보**를 받습니다. 실시간 관측값이나 강수 레이더가 아니며, 화면의 "지금 날씨"도 지금 시각의 예보 값입니다. 같은 좌표는 30분 동안 DB 캐시(`weather_records`)를 씁니다.

출발 시각은 지금부터 24시간 안, 보호자 가능 시간대의 정시마다 평가합니다.

```text
시간대 점수 = 0.55 × 날씨 쾌적도 + 0.15 × 일정 적합 + 0.10 × 일조 + 0.10 × 학습된 시간대 선호 + 0.10 × 가까운 시간
```

| 규칙 | 값 |
|---|---|
| 비 오는 시간 | 강수량 0.3mm 이상 또는 강수 확률 60% 이상 |
| 추천 제외 시간 | 시간당 3mm 이상의 강한 비, 산책 제외 온도, 초속 14m 이상 바람 |
| 기온 쾌적도 | 쾌적 구간 안은 100점. 벗어나면 제외 온도까지 선형으로 0점. 쾌적 상한 −2°C를 넘고 습도 70% 초과면 감점 |
| 바람 | 초속 5m까지 100점, 14m에서 30점 |
| 자외선 | 낮이고 자외선 지수 5 초과면 1당 10점 감점 |
| 비 오기 전 | 3시간 안에 비가 오면 비 전까지만 걷도록 시간을 줄임. 12시간 앞까지 살핌 |
| 여러 번 산책 | 하루 횟수만큼, 3시간 이상 떨어진 시간대를 고름 |

산책 구간의 시간들을 평균과 최악값으로 함께 봅니다. 추위와 더위가 심하면 권장 시간과 거리를 줄입니다(쾌적 구간에서 5°C 넘게 벗어나면 0.6배, 벗어나면 0.8배).

**시연용 날씨:** 곧 비, 지금 비, 폭염, 한파, 폭우 시나리오와 `WEATHER_PROVIDER=mock`은 "시연용"으로 표시하고, 활동 통계에서 빼며, 실제 날씨처럼 말하지 않습니다.

## 환경 특성

| 항목 | 데이터 | 측정 방식 |
|---|---|---|
| 경로, 거리 | OSRM 도보 경로(시드 코스), 공개 GPX(Valhalla 경로), 사용자 기록 | 시드 코스는 미리 구축해 `data/courses*.json`에 저장 |
| 차량 노출 | OSM 도로 등급(보행 전용, 생활도로, 큰 도로) | 경로 10m 간격 표본에서 가장 가까운 도로의 등급 비율 |
| 조명 | OSM `lit` 태그 | 경로의 50% 이상에 기록이 있을 때만 사용. 아니면 확인 불가(팀 추정 병기) |
| 노면 | OSM `surface` 태그 | 기록이 부족하면 확인 불가(팀 추정 병기) |
| 그늘 | OSM 나무, 숲, 가로수 기록 근접 비율 | 기록이 없으면 사실로 쓰지 않음 |
| 공원 | OSM 공원 면 | 경로의 1% 이상이 공원 안이면 공원 코스(시드 코스 16개의 팀 판정과 맞춤) |
| 시설 | OSM 화장실, 음수대, 동물병원, 경찰시설, CCTV 등 | 미리 수집한 `data/places*.json`. 동물병원 200m, 그 밖 60m 안 |
| 혼잡도, 난이도, 동반 가능 여부 | 팀 추정 | "추정"으로 표시 |

시드 코스의 환경값은 `scripts/enrich_courses.py`로 미리 계산했습니다. 내 산책길을 추천 후보로 등록하면 응답 뒤 Overpass로 같은 함수(`environment_service.py`)를 써서 측정하고, 산책길 자동 생성의 후보는 Geofabrik 추출본(.osm.pbf)에서 뽑은 서울 타일(`backend/app/data/osm/seoul/`, 689개, 자료 날짜 2026-10-30)로 측정합니다. 타일 범위 밖은 확인 불가입니다.

## 안전 평가

`safety.py`가 코스와 출발 시각마다 11개 항목의 상태(양호, 주의, 위험, 확인 불가)와 출처(예보, OSM 기록, 팀 추정, 시연용, 데이터 없음)를 매깁니다.

| 원칙 | 구현 |
|---|---|
| 개인화 점수와 관계없이 제외, 경고 | 위험한 날씨와 차단 조건은 제외. 위험 수준은 양호·주의 코스 뒤로 보내고 강한 경고 표시 |
| 데이터가 없으면 안전하다고 보지 않음 | 데이터가 없는 항목은 40점으로 계산. 점수에 들어간 항목의 25% 이상이 데이터 없음이면 "양호"로 판단하지 않음 |
| 없는 항목을 따로 표시 | 항목별 "확인 불가"와 출처별 비중(`data_quality`) 표시 |
| 실시간과 추정 구분 | 예보, OSM 기록, 팀 추정, 시연용, 데이터 없음으로 나누고 코스 환경 기록일을 함께 표시 |
| 안전 점수와 사고 위험을 동일시하지 않음 | "환경 위험을 비교하는 참고값이며 의학적, 절대적 안전을 보장하지 않음"을 표시 |

**안전 점수**는 항목 점수의 가중 평균입니다. 낮과 밤의 가중치가 다릅니다.

| 항목 | 낮 | 해가 진 뒤 |
|---|---:|---:|
| 기온, 강수 | 각 20% | 각 15% |
| 차량 노출 | 20% | 15% |
| 노면, 시설 | 각 10% | 각 5% |
| 바람, 자외선, 시간대, 조명, 그늘, 공원 | 각 5% | 바람·시간대·공원 각 5%, 조명 30%, 자외선·그늘 0% |

위험 항목이 있거나 50점 미만이면 위험 수준, 주의 항목이 있거나 75점 미만이거나 데이터가 부족하면 주의, 나머지는 양호입니다. 개인화 점수에서 주의 항목마다 1.5점, 위험 항목마다 5점(합계 최대 15점)을 뺍니다.

**차단 조건**(그 시간에 그 코스를 추천하지 않음):

- 비 오는 시간에 비포장 코스
- 체감온도가 쾌적 상한 +6°C 이상이고 30분을 넘는 산책인데 그늘을 확인할 수 없는 코스
- 해가 진 뒤 조명이 위험 수준인 코스(노령견이거나 혼잡 허용도 0.3 미만일 때)
- 초속 10m 이상 바람에 강변 코스

**대체 코스:** 위험 수준이 낮거나 안전 점수가 10점 이상 높은 코스만 대체로 권합니다.

**미세먼지:** 받아 오는 데이터가 아직 없어 "확인 불가"로 표시하고 점수에는 넣지 않습니다. 값이 들어오면 환경부 예보 등급(PM10 81, 151, PM2.5 36, 76µg/m³)으로 주의와 위험을 판단합니다. 사람 기준이므로 참고값입니다.

**위험 기준:** 체감온도, 강수, 바람의 기준값은 이전 버전의 서비스 휴리스틱을 그대로 썼습니다. 수의학적으로 검증한 값이 아닙니다.

## 점수 산식

| 묶음 | 기준 가중치 | 내용 | 데이터가 없으면 |
|---|---:|---|---|
| 반려견 특성 | 25% | 성향(익숙함, 혼잡, 기질) 50%, 활동량에 맞는 거리와 경사 50% | 항상 있음 |
| 사용자 선호 | 25% | 보호자가 입력한 선호 거리, 선호 시간대 | 빼고 나머지로 나눔 |
| 거리·시간 | 20% | 희망 시간, 가능 시간 안에 끝나는지. GPS 기록이 있으면 실제 걸음 속도 반영 | 항상 있음 |
| 날씨·환경 | 15% | 구간 쾌적도, 그늘, 비 겹침, 강변 바람 | 날씨 API 장애 때 빼고 나머지로 나눔 |
| 과거 피드백 | 15% | 조정값. 아래 설명 | 0 |

모든 점수는 0~100으로 맞추고, 데이터가 있는 기본 묶음의 가중치를 합이 100%가 되도록 다시 나눕니다. 신규 사용자는 반려견 특성 41.7%, 거리·시간 33.3%, 날씨·환경 25%입니다.

```text
개인화 = Σ(기본 묶음 가중치 × 점수) + 피드백 비중 × 2 × (피드백 점수 - 50)
피드백 비중 = 15% × n / (n + 1)     (n: 피드백 수. 1건 7.5%, 3건 11.25%, 9건 13.5%)
추천 점수 = 개인화 - 안전 감점 - 미선택 감점
```

거리 적합도는 권장 거리와의 비율을 로그 정규 모양으로 평가합니다. 활동량 적합도는 `100 × exp(−ln(코스 거리 / 권장 거리)² / (2 × 0.45²))`, 사용자 선호 거리는 같은 식에 폭 0.35를 씁니다.

### 지시서 가중치를 적용하면서 바꾼 점

지시서의 25/25/20/15/15를 그대로 썼지만, 피드백만 가중합이 아니라 조정값으로 넣었습니다. 가중합으로 먼저 구현하니 피드백이 없는 코스의 중립값 50이 다른 묶음(대부분 80~100점)보다 낮아, 피드백을 1건 남기면 모든 코스가 4~5점 내려가고 5점을 준 코스의 학습 효과까지 음수가 됐습니다. 조정값으로는 평가하지 않은 코스가 그대로이고, 범위는 최대 ±15점입니다.

v1의 "날씨 25%, 안전 10%"를 줄이거나 뺀 근거는 위 변별력 측정입니다. 가중치는 `RECOMMENDER_WEIGHTS`로 바꿀 수 있습니다. 이 값은 초기 실험 기준이고, 실제 데이터로 맞춘 값이 아닙니다.

## 순위 결정

| 고려 사항 | 구현 |
|---|---|
| 안전 우선 | 안전 단계(양호·주의 → 위험 → 차단)로 먼저 나누고, 같은 단계 안에서 점수 순 |
| 출발 시각 | 코스마다 가능한 출발 시각을 모두 평가해 `추천 점수 + 0.15 × 시간대 점수`가 가장 높은 시각을 고름 |
| 중복 코스 | 경로의 60% 이상이 다른 코스의 40m 안을 지나면 같은 길로 보고 한 번만 올림. 다른 후보가 없을 때만 겹친다고 알리며 채움 |
| 후보 부족 | 없는 코스를 만들지 않고 있는 만큼만 추천 |
| 탐색 | TOP 3가 모두 다녀온 코스면, 3위와 점수 차가 `3 + 5 × 낯선 길 허용도`(3~8점) 안인 새 코스로 3위를 바꿈. "새 코스 제안" 표시 |
| 미선택 감점 | 추천에 있었지만 그날 다른 코스를 걸은 경우 하루 1점, 최대 3점, 최근 14일. 선호도에는 넣지 않음 |
| 만족도 높은 코스 | 피드백 조정으로 점수 상승. 5점 1건은 약 +4점이며, 시연 조건(두부, 망원과 개포)에서는 1건에 순위가 그대로이고 2건이면 2위가 1위로 오름 |
| 일관성 | 난수를 쓰지 않음. 같은 입력은 같은 순위 |

**지역 분산은 구현하지 않았습니다.** 서비스 지역이 동네 하나라 코스 경로 중복 제거로 대신합니다.

## 개인화

| 단계 | 쓰는 정보 |
|---|---|
| 신규 사용자 (콜드 스타트) | 프로필과 입력한 선호만. 피드백 비중 0, "반영하지 않았어요" 표시 |
| 선호를 입력한 사용자 | 사용자 선호 묶음(선호 거리, 선호 시간대) 25% |
| 산책 기록이 있는 사용자 | 방문 수(익숙함), GPS 기록 2회 이상부터 개인 걸음 속도(0.7~1.5배) |
| 피드백이 있는 사용자 | 아래 피드백 학습 |

로그인한 보호자에게는 시연 보호자용 "집 근처" 표시를 적용하지 않고, 내 산책길과 실제 방문 기록만 익숙한 길로 봅니다. 시연 보호자는 기존 문장을 유지합니다. 익숙한 길을 좋아하는 반려동물은 좋았던 코스에 가산점을, 새 길을 좋아하는 반려동물은 세 번 이상 간 코스에서 감점을 받습니다. 싫어한 코스(선호 40점 미만)는 자주 가도 "익숙해서 좋은 코스"로 치지 않습니다.

## 피드백 학습

외부 AI 호출 없이 직접 구현한 온라인 학습입니다(`preference.py`).

| 학습 대상 | 방식 | 값 |
|---|---|---|
| 코스 선호 | 최근 피드백 가중 베이즈 축소 평균 | 사전값 50, 사전 강도 1.5건, 최근 가중 감쇠 0.9 |
| 코스 특성 가중치 | 정규화 LMS 선형 모델(코스 특성 11개: 공원, 밝은 길, 포장길, 한적한 길, 그늘, 강변, 숲길, 동네 골목, 짧은 코스, 긴 코스, 오르막) | 학습률 0.3. 피드백이 없는 코스는 예측값이 중립(50)에서 벗어난 만큼의 0.4배만 반영 |
| 시간대 선호 | 시간대(오전 5~11시, 점심 11~14시, 오후 14~18시, 저녁 18~24시, 새벽 0~5시)별 축소 평균 | 사전값 50 |

피드백은 산책 만족도, 반려동물 만족도, 재방문 의향, 난이도를 합쳐 0~100점 신호로 바꿉니다. 코스 선호에서는 날씨 만족도를 뺍니다. 비 오는 날의 나쁜 경험은 코스 탓이 아닐 수 있어서, 날씨가 나빴던 산책은 표본 가중치를 절반으로 줄입니다.

| 행동 | 신뢰도 | 쓰는 곳 |
|---|---|---|
| 산책 후 만족도 | 강함 (1.0) | 코스 선호, 비슷한 코스로 일반화, 선호 거리 |
| 피드백 없이 끝낸 산책 | 약함 (0.3) | 선호 거리 |
| 재방문 | 중간 | 익숙함 (성향 점수) |
| "힘들었어요", "쉬웠어요" | 강함 | 그 거리를 0.8배, 1.2배로 보고 선호 거리 계산 |
| GPS 기록의 실제 시간 | 2회 이상부터 | 예상 시간을 개인 걸음 속도로 보정 (0.7~1.5배) |
| 추천 카드 선택, 산책 시작 | 기록만 | 지표에만 쓰고 학습에는 넣지 않음 |
| 추천에 있었지만 그날 다른 코스를 걸음 | 약한 부정 | 하루 1점, 최대 3점, 최근 14일. 선호도에는 넣지 않음 |
| 추천만 보고 아무것도 안 함 | 쓰지 않음 | 부정 평가로 보지 않음 |
| 시연용 걷기 | 일부만 | 시연 흐름을 위해 코스 선호 학습에는 넣고, 선호 거리, 걸음 속도, 미선택, 지표에서는 뺌 |

같은 피드백이 겹쳐 반영되지 않도록 v1의 "선택 이력"과 "익숙한 길 보너스"를 뺐고, 학습한 거리는 별도 점수로 켜지 않고 권장 거리를 표본 수만큼(2건이면 1/3) 옮기는 데만 씁니다. 별도 점수로 켜면 5점 2건에 다른 코스가 5~12점 떨어졌습니다.

엔진은 같은 날씨에서 학습 상태만 비운 기준선을 함께 계산합니다. 응답의 `learning_delta`와 `rank_change`는 이 기준선과의 차이이므로 피드백의 효과만 보여 줍니다.

## 추천 설명과 LLM

**계산 문장(항상):** `explain.py`가 계산 결과와 코스 데이터로 문장을 조립합니다. 데이터에 없는 시설은 문장에 나올 수 없고, 팀 추정값을 사실처럼 말하지 않습니다. 코스 카드의 **점수 근거 보기**에 항목별 근거(`reason.basis`)와 출처를 반려견 특성, 사용자 선호, 거리·시간, 날씨, 안전, 과거 선호도 순으로 보여 주고, 쓰지 않은 항목은 "반영하지 않았어요"라고 밝힙니다. 점수 계산식(개인화 - 감점 = 추천 점수)도 함께 표시합니다.

**LLM 문장(선택, `LLM_PROVIDER=ollama`):**

1. 엔진이 순위와 점수를 확정해 저장합니다.
2. 화면은 계산 문장을 먼저 보여 줍니다.
3. `POST /recommendations/{id}/explain`이 근거 자료(점수 제외)를 로컬 Ollama(`gemma4:e4b`)에 보냅니다.
4. `explain_guard.py`가 돌아온 문장을 검사합니다.
5. 통과한 문장만 `reason.llm_summary`에 저장하고, 아니면 계산 문장을 그대로 씁니다.

| 검사 | 기준 |
|---|---|
| 이름 | 반려동물 이름이 들어가야 함 |
| 길이 | 15~200자 |
| 단정 표현 | "안전합니다", "보장", "치료", "건강에 좋", "문제없", "무조건", "완벽" 등 금지 |
| 위치 표현 | "공원 내", "코스 안", "바로 앞", "바로 옆" 등 근거 없는 위치 금지 |
| 확인 불가 항목 | 데이터가 없는 항목을 사실처럼 말하면 거부 |
| 시설과 숫자 | 근거 자료에 없는 시설과 숫자를 말하면 거부 |

LLM은 점수, 순위, 안전 판단에 관여하지 않습니다. 날씨를 확인하지 못한 추천은 근거 자료가 사실이 아니므로 LLM 문장을 만들지 않습니다.

## 대체 전략

| 상황 | 동작 |
|---|---|
| 날씨 API 장애 | 모의 날씨로 시간표는 계산하지만 날씨 항목은 "확인 불가", 날씨·환경 묶음은 제외. "산책하기 좋아요"라고 말하지 않고 LLM 문장도 만들지 않음 |
| 예보 없음 (`no_forecast`) | 나쁜 날씨와 구분해 "예보를 받지 못했다"고 안내 |
| 가능 시간 없음 (`no_window`) | 24시간 안에 산책 가능 시간이 없다고 일정 확인을 안내 |
| 코스 없음 (`no_candidates`) | 함께 걸을 수 있는 코스가 없다고 안내 |
| 모든 시간이 위험 (`unsafe`) | 코스 대신 제외 이유와 실내 대안 안내 |
| 안전 데이터 부족 | 확인 불가 항목을 나열하고 "양호"로 판정하지 않음 |
| 후보가 적음 | 있는 만큼만 추천. 겹치는 코스는 다른 후보가 없을 때만 알리고 채움 |
| LLM 꺼짐, 실패, 검증 실패 | 계산 문장 유지, 점수 불변 |

`status` 값으로 화면 제목을 달리합니다.

|---|---|---|
| 순위 | Precision@3, Recall@3, Hit Rate@3, NDCG@3 | 이 추천으로 걸었거나 추천 뒤 7일 안에 만족도를 남긴 코스가 정답 후보. 4점 이상을 맞는 추천으로, 점수는 등급 관련도로 씀 |
| 품질 | 선택률, 시작률, 완료율, 평균 만족도, 재방문율 | 시연용 걷기 제외. 선택과 시작을 기록하기 전의 추천은 선택률과 시작률의 분모에서 뺌 |
| 안전 | 위험 코스 추천 비율, 필터 통과율, 데이터 없음 비중, 날씨 데이터 나이 | 추천 이력 기준 |
| 개인화 | 반려동물 간 차이, 반복 추천률, 새 코스 비율, 피드백 전후 만족도 변화 | 같은 날 다시 누른 추천은 반복으로 세지 않음 |

**추천 후 저장률은 측정하지 않습니다.** 추천 코스와 "나만의 산책길" 저장이 연결되어 있지 않아 `null`과 이유를 돌려줍니다.

**데이터 구분:** `user`는 로그인한 보호자, `demo`는 시연 보호자의 기록입니다. 시연용 걷기는 행동 지표에서 뺍니다. 표본이 30건 미만이면 `reliable`이 `false`이며, 순위와 행동 지표는 각자의 표본으로 판단합니다. **`user`에도 팀의 시험 계정이 섞일 수 있어, 실제 서비스 전까지는 성능 근거로 쓰지 않습니다.**

### 오프라인 2: 합성 사용자 (시뮬레이션, 가상 데이터, 120마리, 20일)

코스 특성에 대한 숨은 취향을 무작위로 정한 가상 반려견이 추천을 받고 산책하고 피드백을 남깁니다. **취향 모형을 팀이 만들었고 엔진의 학습 특성과 같은 축을 써서 학습에 유리합니다. 버전 사이의 경향을 볼 뿐 실제 성능이 아닙니다.** 표의 값은 1~5일 → 16~20일 평균입니다.

## 한계

- **실제 사용자 성능:** 선택률, 만족도, 피드백 전후 변화를 측정할 데이터가 없습니다. 위의 시뮬레이션 결과로 대신할 수 없습니다.
- **현재 위치와의 거리:** 추천 요청에 위치를 받지 않습니다. 동네 하나를 서비스하고, 위치를 저장하지 않는다는 원칙과 함께 정해야 해서 넣지 않았습니다.
- **미세먼지 데이터:** 판단 기준만 있고 받아 오는 제공자는 없습니다.
- **실시간 강수:** 시간별 예보로 판단합니다. 관측이나 레이더로 지금 내리는 비를 감지하지 않습니다.
- **코스 환경 불만, 접근성 문제:** 피드백 화면에 항목이 없고 메모는 분석하지 않아 학습하지 않습니다.
- **추천 후 저장률, 산책길 저장을 긍정 신호로 쓰기:** 저장한 산책길과 추천 코스가 이어져 있지 않습니다.
- **위험 기준과 가중치의 타당성:** 수의학 자료나 실제 데이터로 검증하지 않았습니다.
- **코스 품질:** 조명과 노면은 대부분 OSM에 기록이 없어 팀 추정이며, 팀이 현장을 걷지 않았습니다.
- **1위 쏠림:** 망원에서 코스 하나의 1위 점유가 35.2%로 늘었고 원인을 다 찾지 못했습니다.
- **관리자 화면:** 명령으로만 집계합니다. 만족도 하락 자동 알림은 없습니다.

## 향후 개선

### 머신러닝 도입 검토

지금은 도입하지 않습니다. 학습할 실제 피드백이 0건이고, 코스도 지역당 6~10개라 순위 학습 모델의 입력이 부족합니다. 순위 계산은 `Ranker` 인터페이스로 분리되어 있어, 평가에서 규칙 기반보다 나을 때 바꿔 끼울 수 있습니다.

| 모델 | 필요한 것 | 판단 |
|---|---|---|
| Content-Based | 지금의 코스 특성 학습이 이미 이 방식 | 유지. 특성을 늘리는 쪽으로 개선 |
| Collaborative Filtering | 반려동물 다수와 코스 다수의 평가가 겹쳐야 함 | 지역별 코스가 적고 사용자가 없어 보류 |
| Hybrid | 위 둘 | Collaborative가 가능해진 뒤 |
| LightGBM, XGBoost 순위 학습 | 추천 노출과 결과 수천 건 이상 (팀의 대략적인 판단이며 실험으로 정한 값이 아님) | `recommendation_items`와 이벤트가 학습 자료가 됨. 쌓인 뒤 같은 지표로 오프라인 비교 후 온라인 비교 |

도입 조건은 같은 기간의 실제 기록에서 안전 지표를 해치지 않으면서 NDCG@3과 평균 만족도가 규칙 기반보다 나은 것입니다. 안전 단계는 학습 모델로 바꾸지 않고 앞 단계 필터로 유지합니다.

### 다음 제안

1. 실제 사용자 피드백을 모아 `online` 지표부터 확인하고, 그 값으로 피드백 비중과 탐색 폭을 조정합니다.
2. Open-Meteo Air Quality API로 미세먼지를 연결합니다. 새 외부 API이므로 `docs/EXTERNAL_RESOURCES.md`에도 적어야 합니다.
3. 피드백 화면에 불만 이유(거리, 환경, 접근성)를 넣어 학습합니다.
4. 위치 사용을 정하면, 저장하지 않는 조건으로 출발점까지의 거리를 후보 생성에 넣습니다.
5. 망원의 1위 쏠림 원인을 찾고, 필요하면 같은 반려견에게 반복되는 1위를 조정합니다.
